### VERDICT

- **consumer content localization today:** split. Menu (dishes/categories/modifiers) via the storefront `/public` API is **monolingual, needs building** (single DB string, no locale signal). Restaurant brand/marketing copy and the Expo app's discovery content are **already trilingual/client-picks** (`consumer` module + mobile `pickI18n`). Recipe/ingredient names are **already locale-aware but server-collapsed to one locale**.

- **to give guests a content locale we must:**
  - Add a **locale signal** to the `/public` storefront endpoints (none exists) — query param or header, plus a table-session locale field for anonymous guests.
  - Add **trilingual storage** for menu content (`MenuItem/MenuCategory/ModifierGroup/ModifierOption` are single `String`) — or resolve names through the catalog layer that already carries `{hy,ru,en}`.
  - Wire the QR web app to **send** its locale (today `next-intl` is chrome-only and never sends locale to the API) and to seed the guest locale from the restaurant default when no cookie.
  - Add a **branch/restaurant default locale as guest fallback** — restaurant has `defaultLanguage`, **branch has none**.
  - For `CustomerIngredientResponse`, thread the **guest locale** into `RecipeDetailAssembler`/`DishProjectionResolver` (currently defaults `'en'`); the catalog resolution already produces the trilingual name, so this is a plumbing change, not a data change.

- **server-side locale needed:** at the **storefront read path** (menu render is server-built in `PrismaPublicStorefrontQuery`/use-cases, so the collapse-to-locale must happen server-side unless DTOs are changed to emit all three) and at the **recipe/ingredient projection** (`DishProjectionResolver` already takes a `locale`). **Fiscal: NO** — receipts should stay on the operational `MenuItem.name`, and guest locale must not be threaded there (no leak today; keep it that way). QR web is client-rendered chrome, so no RSC content-locale need there beyond passing the locale to the API.

- **size read: small–medium.** Small if scope is (a) thread guest locale into the recipe/ingredient projection (catalog name already trilingual) + (b) add a locale signal + branch default. Medium once trilingual **menu** content storage/emission is included, since the storefront DTOs and 4 Prisma models are single-string today.
